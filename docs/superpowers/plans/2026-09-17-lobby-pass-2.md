- **Language.** Code, comments, identifiers, commit messages and file names are **English**. Only user-facing UI strings are Chinese. ### Task 1: `core/checkin.ts` — the daily check-in state machine

**Files:**
- Create: `game/assets/scripts/core/checkin.ts`, `game/assets/scripts/core/checkin.ts.meta`
- Modify: `game/assets/scripts/core/index.ts`
- Test: `logic/tests/checkin.test.ts`

**Interfaces produced** (later tasks consume these exact names):

```ts
export const CHECKIN_VERSION = 1;
export const CHECKIN_REWARDS: readonly number[]; // [20,20,30,30,40,40,100]
export interface Checkin { version: number; day: number; last: string; }
export function emptyCheckin(): Checkin;
export function parseCheckin(text: string | null): Checkin;
export function serializeCheckin(c: Checkin): string;
export function todayKey(now: Date): string;              // 'YYYY-MM-DD', LOCAL time
export function canClaim(c: Checkin, today: string): boolean;
export function claim(c: Checkin, today: string): { checkin: Checkin; coins: number };
export function nextReward(c: Checkin, today: string): number;
```

**The rules, stated once:**

- `day` is 0 when nothing has been claimed, otherwise 1..7 — the position in the cycle **already claimed**.
- `last` is the `todayKey` of the most recent claim, `''` when none.
- `canClaim(c, today)` is `c.last !== today`.
- `claim` advances: if `last` is literally yesterday, `day + 1`; otherwise the streak is broken and it restarts at 1. After 7 it wraps to 1.
- `nextReward` is `CHECKIN_REWARDS[(the day `claim` would land on) - 1]`.
- `parseCheckin` **never throws** — a corrupt or absent string returns `emptyCheckin()`. Same contract as `parseWallet`; read it and match it.

**Local time, deliberately.** `todayKey` uses the device's local date. A single-player game with no server has no better clock, and the alternative — UTC — would flip the day at 08:00 for a Chinese player. A player who moves their device clock gets extra coins; that is an accepted cost and belongs in the docblock.

- [ ] **Step 1: Write the failing tests** covering: empty parse, round-trip, corrupt input, `canClaim` twice in one day, consecutive-day streak to 7 and wrap to 1, one-day gap resets to 1, a multi-day gap resets to 1, `nextReward` on each of those, and `todayKey` across a month boundary and a year boundary.
- [ ] **Step 2: Run them, confirm they fail** — `cd logic && npx jest tests/checkin.test.ts`
- [ ] **Step 3: Implement** `core/checkin.ts`.
- [ ] **Step 4: Run them, confirm they pass.** Then the whole suite minus `level-gen`.
- [ ] **Step 5: Commit** both the `.ts` and the `.ts.meta`.

### Task 2: the wallet backfill

**Files:**
- Modify: `game/assets/scripts/core/wallet.ts`, `game/assets/scripts/view/GameController.ts`
- Test: `logic/tests/wallet.test.ts`

**Interfaces produced:**

```ts
export function coinsFromProgress(p: Progress, levelCount: number): number;
```

It sums `COIN_FOR_STARS[bestStars(p, level)]` over levels 1..levelCount — the total a player *would* have been paid had the wallet always existed.

**The wiring**, in `GameController`'s load path beside `parseWallet(loadWalletText())`: if the stored wallet is below `coinsFromProgress`, raise it to that figure and save. Never lower it — coins from a future source (a check-in, a purchase) are not derived from progress and must survive.

The docblock must say why this is safe against the "clear → wipe → clear again" farm the original design worried about: the wipe clears the wallet **and** the progress together, so the backfill computes 0 on the next load.
