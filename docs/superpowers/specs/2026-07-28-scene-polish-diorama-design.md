# 场景美术升级(立体停车场 diorama)设计文档 (M5)

> 状态:已通过口头方向确认,待用户书面审阅。
> 日期:2026-07-28
> 前置:M4(卡通美术+手感)已完成。本milestone在其基础上做整体场景重做。

## 目标

把当前"漂浮在渐变底上的三条元素"升级为一个**统一的立体停车场场景(diorama)**:所有元素落在一块圆角平台上、有阴影落地、网格车在停车场地面里、顶部是**候车厅旋转转盘**(乘客平滑坐着转圈)。车和乘客造型同步重做得更可爱。全程仍**零外部素材**(代码几何体+代码材质),核心逻辑不动。

## 硬约束

- **纯视图层**:`game/assets/scripts/core/` 与 `logic/` 一行不改;44 测试保持绿。
- **零外部素材**:仅 Cocos 内置基元 + 代码材质 + M4 已生成的音效。
- **保留交互**:`BOARD_TILT=52`、固定相机、射线→板平面→gridRoot 局部→`pickCar` 流程不变。拾取按车 root 的 footprint AABB,重做车造型只改 root 内部的子节点,不改 root 位置/尺寸,故拾取不受影响。
- **性能**:目标微信小游戏,注意 draw call / 三角面;转盘乘客用补间移动而非每帧重建节点。
- **平台**:自定义 "Builtin" 渲染管线下,`builtin-standard` 光照已验证可用(M4)。**阴影在该管线下能否用需 Task A 先验证**;不行则用假阴影兜底(见下)。

## 现状短板(要解决的)

1. 无阴影,元素像漂浮 → 加阴影落地。
2. 三条元素(环/车位/网格)各自漂浮、中间大片空白 → 用平台+停车场地面收成整体。
3. 车顶白箭头丑、造型偏积木 → 重做,方向靠车头朝向+车灯表达。
4. 光照发灰发闷、背景太空 → 调光+背景装饰。
5. 乘客造型偏简单 → 重做更可爱。

## 架构:新增/改动文件

新增(视图层 `game/assets/scripts/view/`):
- `scene-stage.ts` — 圆角平台/托盘 + 停车场地面(沥青色 inset + 车道线)+ 背景(天空色板/云/暗角)。取代 `environment.ts` 里 floor/back 那几块粗糙 slab(environment 保留灯光/阴影设置职责)。
- `turntable-view.ts` — 候车厅转盘:装饰圆台 + `capacity` 个"车站"世界位置;乘客节点在相邻车站间**补间平滑移动**(每 tick 前移一站),上车口=最靠近停车场的车站。取代现有 `loop-view.ts` 的椭圆点阵。

改动:
- `environment.ts` — 增加**阴影设置**(scene.globals.shadows:ShadowMap;方向光 shadowEnabled;或验证失败后改由 scene-stage 提供假阴影)。灯光调优(更强主光+冷暖对比)。
- `car-builder.ts` — 重做:更圆润比例、**挡风玻璃 + 车灯 + 车头朝向 `dir`**(去掉车顶箭头);方向由车头朝向 + 前灯表达。可选:贴地小箭头贴片(若纯朝向不够直观)。
- `passenger-builder.ts` — 重做更可爱(比例/配色微调,可加简单手臂或圆润身形)。
- `parking-view.ts` — 车位嵌入停车场地面(与 scene-stage 协调),造型收尾。
- `GameController.ts` — 用 `turntable-view` 替换 `loop-view` 的接线;上车飞人起点改用转盘车站世界坐标;把 stage 接入 buildBoard;假阴影(如启用)随车/人创建。
- `loop-view.ts` — 若被 turntable-view 完全取代则删除;否则保留其椭圆布局作后备。

## 关键设计:候车厅转盘(平滑riding)

- 圆周上 `capacity` 个**固定世界车站**,车站 0 = 上车口(最靠近停车场一侧)。底部一块**装饰圆台**(可缓慢自转纯装饰)。
- 视图每 tick 收到核心的 `ring[]`(每个车站的内容,权威)。乘客用**补间**在相邻车站间平滑前移一站(时长≈TICK),从而看起来像坐着转盘转圈。
- 补位(队列→环)时新乘客在"入口车站"淡入/弹入;上车(车站 0)时乘客沿弧线飞向对应车(复用 M4 Task6 的飞人)。
- 与核心同步:不改核心 LoopSystem;view 只读 `ring` 反映到转盘。机制细节(节点复用/补间/显隐)在实现计划里定,预览校正。

## 关键设计:阴影

- **首选 ShadowMap**:`director.getScene().globals.shadows` 开启、type=ShadowMap、设 shadow distance/size;`DirectionalLight.shadowEnabled=true`;地面/平台作为接收面。Task A 先在预览验证该管线下是否出影。
- **兜底假阴影**:若 ShadowMap 在 Builtin 管线下不工作,则给每辆车/每个乘客贴一片**贴地深色半透明椭圆**(unlit + 透明材质,或深色实心椭圆),随物体移动。保证"落地感"这一核心收益不丢。
- Task A 的交付明确二选一,后续任务按选定方案接线。

## 关键设计:车造型 + 方向

- 更圆润:车身分段更柔和,加**挡风玻璃**(斜面深色玻璃)、**前后车灯**(小亮块)、可选顶灯。
- **方向**:车的"车头"朝向其 `dir`,前灯在车头 → 玩家一眼看出往哪开。去掉车顶白箭头。若纯朝向在俯视下不够直观,补一个**贴地箭头贴片**指向 `dir`(比车顶凸起自然)。
- root 位置/footprint 不变,只重排 root 内部子节点 → 拾取不受影响。

## 分阶段(SDD,每阶段截图确认)

- **A 阴影 + 光照 + 背景**:验证/接入阴影(或兜底假阴影),调光,天空/暗角背景。交付:元素落地、通透、有背景。
- **B 平台 + 停车场地面**:圆角平台托盘 + 网格区停车场地面 + 车道线。交付:元素被收进一个整体场地。
- **C 候车厅转盘**:turntable-view,乘客平滑riding,上车口。交付:顶部是会转的候车厅,乘客坐着转。
- **D 车造型重做**:挡风/车灯/朝向,去箭头。交付:车更可爱、方向直观。
- **E 乘客造型重做**:更可爱。交付:转盘上是更精致的小人。
- **F 车位嵌入 + 构图收尾**:车位融进停车场、整体间距/配色/相机微调。交付:完整统一的场景。

## 风险

- **阴影管线兼容**:最大不确定项,Task A 优先验证,有假阴影兜底。
- **转盘平滑同步**:补间与离散 tick 的衔接需预览调参(TICK=0.12 较快,补间时长要匹配)。
- **性能**:平台/地面/转盘/阴影都增面与 draw call,注意基元分段数与材质缓存复用。
- **看不到渲染**:仍靠逐阶段截图,故小步交付。
